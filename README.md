# Personal Messenger PWA

Персональный мессенджер: веб-приложение PWA и сервер. Поддерживает личные и групповые чаты, сообщения, изображения, файлы, push-уведомления, бесплатные аудио- и видеозвонки через WebRTC.

## Состав

- React/Vite PWA — интерфейс для Safari, Chrome и настольных браузеров.
- FastAPI — авторизация, чаты, файлы, WebSocket и сигналинг звонков.
- PostgreSQL — пользователи, чаты, сообщения и push-подписки.
- coturn — собственный бесплатный TURN-сервер для звонков через мобильные сети и сложный NAT.
- Nginx — раздача PWA и проксирование API/WebSocket.

## Быстрый запуск

```bash
cp .env.example .env
./generate-vapid-keys.sh
# внесите ключи и секреты в .env
docker compose up --build -d
```

Локально приложение откроется на `http://IP-СЕРВЕРА:8080`.

## HTTPS обязателен

Камера, микрофон, установка PWA и push-уведомления на iPhone работают на публичном домене только через HTTPS. Установите внешний reverse proxy, например Caddy, Nginx Proxy Manager или Traefik, и направьте домен на порт 8080.

## Настройка звонков

В `.env` задайте:

```env
TURN_HOST=messenger.example.com
TURN_PORT=3478
TURN_REALM=messenger.example.com
TURN_USERNAME=messenger
TURN_PASSWORD=сложный-пароль
```

На маршрутизаторе/фаерволе откройте и перенаправьте на сервер:

- TCP/UDP `3478` — TURN;
- UDP `49160-49200` — медиапотоки TURN;
- TCP `443` — HTTPS веб-приложения.

Без `TURN_HOST` звонки всё равно используют STUN и часто работают в одной сети, но соединение между мобильными операторами или за строгим NAT может не установиться.

## Звонки

В заголовке личного или группового чата есть кнопки:

- `☎` — аудиозвонок;
- `🎥` — видеозвонок.

Есть входящий экран, принятие и отклонение, отключение микрофона/камеры и завершение звонка. Групповой звонок реализован WebRTC mesh: подходит для небольших групп. Для больших конференций нужен отдельный SFU-сервер.

## Особенности iPhone

1. Откройте HTTPS-сайт в Safari.
2. Нажмите «Поделиться» → «На экран Домой».
3. Запускайте приложение с иконки на домашнем экране.
4. Разрешите уведомления, микрофон и камеру.

Push сообщает о входящем звонке на заблокированном устройстве. После нажатия уведомления пользователь открывает PWA и принимает вызов. Обычная PWA не может показывать системный экран CallKit или автоматически включать микрофон в фоне — для этого требуется нативное iOS-приложение.

## Исправление жизненного цикла звонков

В этой версии:
- микрофон и камера запрашиваются только после нажатия «Позвонить» или «Принять»;
- личный звонок завершается для обоих участников при сбросе любой стороной;
- завершение дублируется REST-запросом, поэтому состояние очищается даже при разрыве WebSocket;
- отклонённый звонок не появляется повторно после перезапуска PWA;
- ICE-кандидаты, пришедшие до SDP, временно сохраняются и применяются после установки remote description;
- все MediaStreamTrack, RTCPeerConnection и video.srcObject очищаются при завершении и закрытии страницы.

## Исправление открытия входящего звонка из push

Push о звонке содержит идентификатор вызова. При нажатии service worker передаёт его уже открытому PWA и/или открывает URL `?chat=...&call=...`. Клиент затем запрашивает конкретный активный звонок через `/api/calls/by-id/{call_id}` и показывает экран принятия вызова.

После обновления обязательно пересоберите контейнеры. На iPhone закройте PWA через переключатель приложений и запустите снова; если старый service worker не обновился, удалите и заново добавьте приложение на экран «Домой».

## Ошибка `Docker cache corruption`

В этой сборке удалён непереносимый `package-lock.json`, который содержал адрес внутреннего npm-репозитория. Версии пакетов зафиксированы в `package.json`, а Docker явно использует публичный `registry.npmjs.org`.

Для полной пересборки без повреждённого BuildKit-кэша выполните:

```bash
chmod +x rebuild-clean.sh
./rebuild-clean.sh
```

Скрипт не удаляет именованные тома `db_data` и `uploads`, поэтому база сообщений и загруженные файлы сохраняются. Не запускайте `docker compose down -v`, если нужно сохранить данные.

Если ошибка остаётся на Docker Desktop, перезапустите Docker Desktop и снова выполните `./rebuild-clean.sh`. Крайняя мера — очистка BuildKit из интерфейса Docker Desktop; она удалит только кэш образов, но не должна удалять тома проекта.

## Исправление зависания звонка на «Соединение…»

События принятия звонка и WebRTC-сигналы теперь отправляются через WebSocket с автоматическим резервом через HTTP. Это особенно важно на iPhone: после открытия PWA из push-уведомления WebSocket может подключиться с задержкой.

После обновления выполните полную пересборку frontend и backend:

```bash
docker compose down
docker compose build --no-cache backend web
docker compose up -d
```

Проверьте TURN:

```bash
docker compose logs --tail=100 turn
docker compose exec backend python -c "import os; print(os.getenv('TURN_HOST'), os.getenv('TURN_PORT'))"
```

Для звонков между мобильной сетью и Wi-Fi должны быть доступны UDP/TCP 3478 и UDP 49160-49200. `TURN_HOST` должен быть публичным доменом или публичным IP сервера, а не внутренним адресом Docker или LAN.

## Исправление звонков: надёжный сигналинг и рингтон

- События `call_accept`, WebRTC `offer/answer` и ICE-кандидаты сохраняются в очереди на сервере и дополнительно опрашиваются клиентом каждые 650 мс. Поэтому сигнал не теряется, если PWA на принимающем iPhone открылась позже push-уведомления.
- У вызывающего абонента звучат гудки до ответа, отклонения или сброса.
- В открытом приложении у принимающего абонента звучит рингтон до принятия или отклонения.

### Ограничение iPhone PWA

Когда iPhone заблокирован и PWA не открыта, iOS показывает системное push-уведомление и воспроизводит системный звук уведомления один раз. Непрерывно проигрывать пользовательский рингтон поверх экрана блокировки до ответа веб-приложение не может. Для поведения полностью как WhatsApp с системным экраном входящего звонка требуется нативное iOS-приложение с CallKit и VoIP Push.

## Обновление последовательных звонков

Перед каждым новым звонком клиент закрывает старые RTCPeerConnection, останавливает медиапотоки и завершает оставшиеся активные звонки пользователя на сервере. Это позволяет выполнять второй и последующие вызовы без перезапуска PWA.

После обновления рекомендуется пересобрать frontend и backend без кэша и заново открыть PWA.

## Статус присутствия и адаптивный интерфейс

- В личном чате под именем отображается `в сети` или время последней активности.
- В групповом чате отображается число участников онлайн.
- В списке чатов онлайн-пользователь отмечается небольшой точкой.
- Интерфейс автоматически определяет телефон, планшет или компьютер.
- Учитываются ширина, высота, поворот экрана, экранная клавиатура и safe-area iPhone.
- На телефоне используется одноэкранная навигация, на планшете и компьютере — двухпанельный режим.

## Обновление профиля и времени

- Отображаемое имя меняется нажатием на аватар в верхней панели. Логин для входа при этом не изменяется.
- В профиле можно загрузить фотографию пользователя.
- Время сообщений и последней активности всегда отображается по Москве (`Europe/Moscow`).
- В меню `+` доступны фото/видео, документ и переход к сервису `https://files.igorson.xyz`.

## Быстрые ссылки группового чата

В заголовке каждой группы отображаются три полупрозрачные кнопки. Создатель группы может настроить для каждой название и URL сайта либо deep link приложения. Настройки также доступны в меню группы.


## Отправка файла временной ссылкой

Пункт `+ → Отправить ссылку` теперь работает внутри мессенджера: пользователь выбирает файл, backend сохраняет его и формирует публичную ссылку на 30 дней. Ссылка автоматически подставляется в поле сообщения.

В `.env` задайте:

```env
PUBLIC_SHARE_BASE_URL=https://files.igorson.xyz
SHARE_TTL_DAYS=30
```

Домен `files.igorson.xyz` должен быть направлен на этот же web-контейнер или reverse proxy. Маршрут `/share/` проксируется на backend.

## Multiple files in «Отправить ссылку»

The file picker supports multiple selection. One selected file is shared directly. Two or more selected files are combined into a single ZIP archive on the server and one public link is inserted into the message field. Limits: up to 50 files and 500 MB total before compression.
